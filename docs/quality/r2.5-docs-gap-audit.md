# R2.5 Documentation Gap Audit

Date: 2026-09-14

Author: Codex docs gap audit (delegated), reviewed by the orchestrator

This audit records gaps only. It does not update the audited documents.

## docs/user/user-documentation.md

1. **Severity: major**  
   **Evidence:** `docs/user/user-documentation.md` §15 "Savings Ledger", lines 484-532, and §16
   "Export Savings", lines 536-551. The web user guide already covers the savings ledger, verified
   savings, and the current export screen, but it is savings-only and describes only Excel/PDF.  
   **R2.5 doc change needed:** T040 must add the Reports center, report schedules, weekly cadence,
   tenant reporting timezone behavior, artifact list fields, schedule pause/resume behavior, and
   per-member digest settings/in-app digest status.

2. **Severity: blocker for user-facing falsehoods**  
   **Evidence:** §16 says the export flow shows "a download link appears when complete" (line 549),
   while `apps/api/src/procurepilot_api/modules/exports/storage.py` returns
   `/api/v1/exports/{job_id}/download` (line 42) and the router only implements `POST /exports` and
   `GET /exports/{id}` (`apps/api/src/procurepilot_api/modules/exports/router.py`, lines 18-34).
   R2.5 research R6 confirms the documented `GET /api/v1/exports/{id}/download` link currently 404s.  
   **R2.5 doc change needed:** T040 should keep the user guide aligned with T013/T039: completed
   export/report artifacts download through the authenticated endpoint only after that endpoint is
   actually implemented and audited.

3. **Severity: major**  
   **Evidence:** §16 lists only supplier/date filters (lines 547-548), and no branch filter, CSV
   format, 10,000-row cap, 90-day retention purge, Arabic/RTL PDF behavior, or labels from
   `packages/i18n`.  
   **R2.5 doc change needed:** T040 must document CSV, branch filtering, clear over-cap refusal,
   artifact expiry/purge behavior, Arabic PDF/RTL expectations, and the expanded export kinds:
   `savings_ledger`, `spend_by_supplier`, and `alerts_summary`.

4. **Severity: minor**  
   **Evidence:** The sidebar lists "Savings Ledger" as the route for export workflows (line 126),
   but there is no Reports center entry yet.  
   **R2.5 doc change needed:** T040 should add navigation and screenshots for the Reports center,
   schedule form, digest settings, and the in-app digest view.

## docs/user/mobile-app-user-documentation.md

1. **Severity: major**  
   **Evidence:** §1 and §2 state mobile is deliberately narrow, with sign-in, biometric unlock,
   role-aware Home, and sign-out only (lines 39-54, 62-85). §11 says product, supplier,
   quotation, matching, compare, and savings pages are not mobile surfaces (lines 358-360).  
   **R2.5 doc change needed:** No R2.5 mobile feature appears in T040. The doc should still get a
   small post-R2.5 note if weekly digest delivery produces mobile-visible notifications or links;
   otherwise it should explicitly say report schedules, Reports center, exports, and digest
   settings remain web-only.

2. **Severity: major**  
   **Evidence:** §10 "Security, Privacy, and Auditability" says mobile commercial audit trails are
   created by web workflows (lines 309-324), and §12 known limitations do not mention reporting or
   digests (lines 371-380).  
   **R2.5 doc change needed:** If digest email/in-app links can be opened from mobile, document the
   security boundary: mobile remains an awareness surface, while artifact download, schedule
   mutation, export creation, and digest subscription management remain authenticated web/API
   workflows.

3. **Severity: minor**  
   **Evidence:** The doc repeatedly positions mobile as an awareness layer for branch users (lines
   56-58, 125-127), but R2.5 adds branch-filtered reports and digests.  
   **R2.5 doc change needed:** Schedule separately unless mobile scope changes: clarify whether
   branch-filtered digest links are supported on mobile or redirect users to web.

## docs/architecture/api-specification.md

1. **Severity: blocker for user-facing falsehoods**  
   **Evidence:** `GET /exports/{id}` documents a `download_url` value of
   `/api/v1/exports/.../download` (lines 1030-1061), but there is no documented
   `GET /exports/{id}/download` section, and the implementation router has no such route
   (`apps/api/src/procurepilot_api/modules/exports/router.py`, lines 18-34). R2.5 spec FR-005
   explicitly calls this documented-but-unimplemented endpoint out (spec lines 202-205).  
   **R2.5 doc change needed:** T039 must document the delivered download endpoint precisely:
   authenticated lookup, expiring signed URL or stream, audit event, content type, expired/purged
   artifact behavior, and 404 for cross-tenant access.

2. **Severity: major**  
   **Evidence:** `POST /exports` is documented as "asynchronous savings-ledger export" with kind
   fixed to `savings_ledger` and format `xlsx` or `pdf` (lines 999-1008).  
   **R2.5 doc change needed:** T039 must replace the savings-only contract with the R2.5 kind/format
   matrix: CSV/XLSX for all kinds and PDF for `savings_ledger` and `alerts_summary`; it must also
   document `spend_by_supplier`, `alerts_summary`, row-cap refusal, retention expiry, and rule
   version/filter snapshots.

3. **Severity: major**  
   **Evidence:** The API spec says `branch_id` is accepted but not meaningful because
   `SavingRecord` has no `branch_id` (lines 897-900 and 1004-1007). The implementation is stricter:
   `ExportService.create_job` raises `unsupported_in_phase_1` for non-null `branch_id`
   (`apps/api/src/procurepilot_api/modules/exports/service.py`, lines 21-24).  
   **R2.5 doc change needed:** T039 must document the actual R2.5 behavior after T014: branch
   filter supported with branch visibility validation, not silently accepted, ignored, or refused as
   `unsupported_in_phase_1`.

4. **Severity: major**  
   **Evidence:** There are no `/reports/schedules`, `/reports/artifacts`,
   `/digests/subscriptions`, `/digests/latest`, or `PATCH /tenant` `reporting_timezone` entries in
   the audited API spec. Current `PATCH /tenant` only lists `name` and `default_locale` (lines
   89-95).  
   **R2.5 doc change needed:** T039 must add those endpoints from T007, including cursor
   pagination, idempotency, RBAC, rate limits, cross-tenant not-found semantics, SMTP fallback
   states, and tenant reporting timezone validation.

## docs/architecture/data-dictionary.md

1. **Severity: major**  
   **Evidence:** `Tenant` fields stop at `default_locale`, `platform_invitation_id`, and
   `created_at` (lines 12-25); there is no `reporting_timezone`.  
   **R2.5 doc change needed:** T038 must add `tenant.reporting_timezone text not null default
   'UTC'`, owner-editable through `PATCH /tenant`, with API-level IANA validation.

2. **Severity: major**  
   **Evidence:** There are no `report_schedule` or `digest_subscription` entities. The R2.5 data
   model defines both as new tenant-scoped tables with forced RLS, schedule/digest due indexes, and
   member ownership rules (`specs/012-reporting-hardening/data-model.md`, lines 7-69, 96-100).  
   **R2.5 doc change needed:** T038 must add `report_schedule`, `digest_subscription`, their enums,
   uniqueness constraints, due-list indexes, RLS policy shape, and ownership/RBAC rules.

3. **Severity: major**  
   **Evidence:** `ExportJob` is documented as chunk 4.6 savings-ledger only, with `format` limited
   to `xlsx` or `pdf`, statuses `queued/running/completed/failed`, and `download_url` optional
   (lines 865-890).  
   **R2.5 doc change needed:** T038 must extend `export_job` with `schedule_id`, `rule_version`,
   `expires_at`, `expired` status, `csv` format, expanded report kind values, per-period
   idempotency index, retention purge behavior, and artifact/download audit semantics.

4. **Severity: major**  
   **Evidence:** The implemented value-proof section documents `PurchaseRecord`, `SavingRecord`,
   and `ExportJob`, but no tenant-pinned reporting reader functions or R2.5 audit events.  
   **R2.5 doc change needed:** T038 must add the four SECURITY DEFINER reader functions
   (`reporting_savings_for_period`, `reporting_purchases_for_period`,
   `reporting_alert_snapshot`, `reporting_validity_expiring`) and the `reports.*` /
   `digests.*` audit events listed in the R2.5 data model.

## docs/quality/test-strategy.md

1. **Severity: major**  
   **Evidence:** The current performance section has the compare-grid `< 150 ms` target (lines
   73-78), but it does not require an automated timing regression test. R2.5 FR-025 requires that
   test, and T031 names `apps/web/tests/e2e/compare-grid-performance.spec.ts`.  
   **R2.5 doc change needed:** Add the timing regression gate, CI noise strategy, and reporting of
   the initial bundle `<= 500 kB` plus zero component style budget warnings.

2. **Severity: major**  
   **Evidence:** Accessibility is currently a general axe-core/Lighthouse WCAG 2.1 AA release check
   (lines 16-18, 84, 87-101), but there is no mandatory axe surface list, no EN/AR matrix, and no
   Reports center or digest settings coverage.  
   **R2.5 doc change needed:** Add the FR-026 mandatory surface list: sign-in, dashboard, compare,
   basket split, alerts inbox, supplier scorecard, savings ledger, approval queue, Reports center,
   and digest settings, all in English and Arabic with zero axe-core violations and keyboard-only
   checks for reporting surfaces.

3. **Severity: major**  
   **Evidence:** Security testing lists OWASP ZAP and penetration test (line 17), but does not
   mention a blocking dependency-audit CI job, R2.5 rate-limit checks, signed-URL/storage review,
   SMTP secret handling, or the recorded security review.  
   **R2.5 doc change needed:** Add FR-021/FR-022/FR-023 gates: Python and JavaScript dependency
   audit in CI, recorded security review, rate-limit assertions, and a pentest scope document for
   the pre-G2 gate.

4. **Severity: major**  
   **Evidence:** Tenant isolation is a general backend target (line 31), but there is no isolation
   extension for report schedules, artifacts/export jobs, digest subscriptions, or tenant-pinned
   worker reader functions.  
   **R2.5 doc change needed:** Add the R2.5 isolation test extension from T008/SC-002: cross-tenant
   schedule, artifact, export job, and digest subscription IDs return not found, and worker readers
   cannot expose another tenant's marker rows.

5. **Severity: minor**  
   **Evidence:** Mobile test targets still name future mobile request/approval flows (lines 41-44,
   69-71), while the current mobile user doc says those flows are not shipped.  
   **R2.5 doc change needed:** Schedule as pre-existing debt unless R2.5 changes mobile scope; it
   should not block reporting hardening but should be reconciled before mobile adoption is used as a
   G2 evidence point.

## Cross-Document Contradictions

1. **Severity: blocker for user-facing falsehoods**  
   **Evidence:** User documentation promises a completed export download link
   (`docs/user/user-documentation.md`, line 549), API documentation shows such a link in
   `download_url` (`docs/architecture/api-specification.md`, line 1056), and data dictionary allows
   `download_url` (`docs/architecture/data-dictionary.md`, line 878), but the API router does not
   implement `GET /api/v1/exports/{id}/download`.  
   **R2.5 doc change needed:** T039/T040 must be updated only after T013 lands so docs and code agree.

2. **Severity: major**  
   **Evidence:** The API spec says non-null `branch_id` is accepted but not meaningful (lines
   1004-1007), the data dictionary lists `branch_id` inside `ExportJob.filters` (line 874), and the
   implementation refuses it as `unsupported_in_phase_1` (`ExportService.create_job`, lines 21-24).  
   **R2.5 doc change needed:** T038/T039/T040 must converge on the R2.5 rule: branch filter works
   for report/export/digest surfaces with branch visibility validation.

3. **Severity: major**  
   **Evidence:** The web user doc and API spec frame export as savings-only; R2.5 requires reporting
   artifacts for savings ledger, spend by supplier, and alerts summary.  
   **R2.5 doc change needed:** T039/T040 must avoid implying exports are savings-only after R2.5.

4. **Severity: major**  
   **Evidence:** The data dictionary marks implemented tables as reflecting migrations (lines 5-6),
   but it has no planned section for the R2.5 entities yet; the API/user docs likewise have no
   Reports center or digest sections.  
   **R2.5 doc change needed:** Keep these docs unchanged until R2.5 implementation, then update as
   part of T038/T039/T040 to avoid documenting planned tables/endpoints as shipped too early.

## Recommendation for Wave 16

1. **Fix as part of R2.5 implementation, already tasked:** T038 must update the data dictionary for
   `tenant.reporting_timezone`, `report_schedule`, `digest_subscription`, `export_job` extensions,
   reader functions, and audit events. T039 must update the API specification for reports,
   digests, expanded exports, branch filter behavior, row cap, retention, rate limits, and the
   implemented download endpoint. T040 must update the web user documentation and screenshots for
   the Reports center, schedule form, digest settings, and export hardening.

2. **Fix as part of R2.5 implementation, likely new doc-test task:** The test strategy should be
   updated for the R2.5 gates: compare-grid timing regression, initial bundle and style budgets,
   axe-core mandatory surface list in EN/AR, dependency-audit CI, rate-limit/security review checks,
   pentest scope, and isolation coverage for report schedules, artifacts/export jobs, digest
   subscriptions, and worker reader functions.

3. **Pre-existing debt to schedule separately:** The mobile documentation and test strategy still
   disagree on shipped mobile request/approval capability. Unless R2.5 adds mobile-facing digest
   behavior, keep mobile R2.5 edits limited to web-only/reporting boundary notes and schedule the
   broader mobile documentation/test reconciliation outside the reporting hardening work.
