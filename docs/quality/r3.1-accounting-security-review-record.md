# R3.1 Accounting Integration Security Review

**Feature:** `014-accounting-integration`  
**Review date:** 2026-09-19  
**Scope:** QuickBooks connection lifecycle, synchronization, reconciliation endpoints, provider
write-back exposure, rate limiting, and tenant isolation.

## Review Evidence

| Area | Verification | Result |
|---|---|---|
| OAuth CSRF state | `ConnectionService._generate_state()` signs tenant/member context with HMAC-SHA256, includes a nonce, and `_verify_state()` uses constant-time comparison plus a one-hour freshness window. | Pass |
| OAuth token storage | Access and refresh tokens are encrypted through `shared.token_crypto` before persistence and decrypted only inside the sync service's service-role path. | Pass |
| Provider write-back | `AccountingConnector` exposes authorization, token, company, vendor, and bill reads only. QuickBooks entity synchronization contains no provider create, update, or delete operation. | Pass |
| Endpoint authorization | Connect/disconnect are owner-only; sync and discrepancy resolution require owner or buyer; read endpoints require an authenticated tenant member. | Pass |
| Rate limiting | Manual sync and discrepancy resolution use the tenant/member keyed mutation limiter. The limiter uses endpoint identity rather than raw URL identity, preventing path-ID bucket rotation. | Pass |
| Tenant isolation | Canonical isolation tests cover `accounting_connection`, `synced_vendor`, `synced_bill`, `purchase_bill_match`, and `reconciliation_discrepancy`, including cross-tenant reads and writes. | Pass |
| Historical data on disconnect | Disconnect marks the connection disconnected and preserves synced records; no destructive provider or local data operation is exposed. | Pass |
| Auditability | Connect, disconnect, sync start/completion/failure, and discrepancy resolution emit audit events. | Pass |

## Findings

No open security findings remain for the reviewed R3.1 surface. The implementation retains the
read-only provider boundary and the database-enforced tenant boundary required by the constitution.

## Residual Operational Requirement

Before enabling `quickbooks` mode in production, configure a dedicated encryption key, OAuth client
credentials, redirect URI, and provider environment explicitly through deployment secrets. The
stub mode remains the automated-test default.
