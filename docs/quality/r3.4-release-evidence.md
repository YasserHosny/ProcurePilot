# R3.4 Release Evidence

## Catalogue Refresh Review

The scheduled catalogue refresh path now remains human-authorised end to end:

1. A due schedule enqueues a tenant-scoped catalogue job.
2. The worker creates a normalized CSV preview without changing catalogue prices.
3. The matching queue lists pending previews through authenticated, forced-RLS reads.
4. An owner or buyer claims the preview, approves or rejects it, and the decision is audited.
5. Approval reuses the validated catalogue import and matching pipeline.

## R4.0 exception posture

At the product owner's direction, R4.0 forecasting and reorder-proposal implementation proceeds
while G3 remains unmet. This is an implementation exception, not a gate pass and not commercial
validation. Every stored forecast carries `release_posture = g3_unmet`; less than 180 days of
history is labelled provisional; synthetic fixtures are test-only; and the UI requires a human
to prepare a draft purchase request. The feature does not create, submit, approve, or send a
purchase order automatically. G3 metrics above remain the source of truth and must be rerun after
real connected usage accumulates.
