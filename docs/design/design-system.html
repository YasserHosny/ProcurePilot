Every number traces back to the quote it came from.

Ledger is ProcurePilot's design system. Supplier quotes arrive as emails, PDFs and phone photos, in Arabic and English. The interface turns them into one comparable line, with an explicit currency and a visible folio back to its source, and leaves the purchase decision to a person.

Brand alignment Colours and type follow docs/brand (Converge, adopted 2026-10-14): Navy #0B2545, Teal #12A594, Mist #C9D6E3, Paper #F4F6F9 and Readex Pro. One documented exception, recorded in docs/brand/README.md: figures in tables and money columns use Noto Kufi Arabic, because Readex Pro has no tabular figures.

Principles

A financial tool used by buyers, owners and branch staff in a busy working day. Calm and precision beat spectacle.

Evidence sits beside the number

Every price, total and saving carries a folio: document id, page and extraction confidence. A number with no source is never shown as fact. The same element appears in extraction review, the quote comparison and the analyst's citations.

descriptionQ-0412 · p.2 · 88%

Currency is part of the number

No amount appears without its currency, and the currency is never guessed. When a quote does not state one, the line goes to review with the home currency only as a suggestion.

EGP 1,250.00 ١٬٢٥٠٫٠٠ ج.م.

A double rule marks a verified total

Borrowed from the accounting ledger: a double underline means a total is closed and reconciled against its documents. It appears under verified totals only, so it keeps its meaning.

EGP 439,755.00

A person authorises

Automation prepares and routes; it never buys. Approval buttons name the action, state what happens next, and appear only for people who hold the authority.

The meaning rule: three signals that are never borrowed

  • The double rule marks verified totals only, totals reconciled against a source document or purchase order. Never under a headline figure or KPI, never as decoration.
  • Teal means best offer or money saved, and nothing else. It is not the brand colour for buttons, not success, not a link colour.
  • Approved is green, with its shape: the filled circle and tick. Information is blue. The green is deliberately yellower than teal, so an approved chip never reads as money saved.

Colour and tokens

Navy for the brand and for actions, ledger paper for surfaces, and teal reserved for the best offer and money saved, the same job it does in the logo, where the winning bar keeps going as an arrow. Dark mode turns the surfaces navy. Contrast ratios below are computed live from the current token values, so they change when you switch to dark mode.

Primitive ramps

Raw values with no meaning. No component reads them directly; only semantic tokens point at them. Higher numbers are darker. Mist #C9D6E3 is navy 200.

Three token layers: primitive, semantic, component

A selector reads its own layer or the one directly beneath it. A component reading a primitive such as --pp-navy-800 fails review. Dark mode changes only the semantic layer; switch the theme to watch the first column move while the third stays put. The counts below are taken from the token sheet that styles this page.

Data visualisation

Six category colours led by navy, and a five-step navy ramp. Every category colour clears 3:1 on the card in both themes. Teal is not a category colour, and no category colour sits near it: teal appears in a chart only when the value is money saved.

Typography and money

One family for both scripts: Readex Pro, drawn for Arabic and Latin together with matched weights, so a mixed-language screen never looks like two fonts arguing. The scale is the classical one, 12, 14, 16, 18, 21, 24, 36, 48. Weights are 400 and 500 for text and 600 for headings, as in the wordmark. Large Latin headings are tracked −0.02em; Arabic is never tracked. Arabic gets more line height (1.7 against 1.5). Readex Pro has no tabular figures, so numbers in tables and money columns use Noto Kufi Arabic; everything else stays Readex Pro.

Figures in tables: why Noto Kufi Arabic

The same digits in both faces. In Readex Pro, 1111 and 8888 differ in width even with tabular-nums, so columns drift. In Noto Kufi Arabic the two widths are equal, for Latin and Arabic-Indic digits alike. The widths are measured live.

Space, shape, elevation and motion

The 4px scale stays. Corner radius grows with the size of the thing: a chip is crisper than a button, a button crisper than a card. Borders separate; shadow is only for things that float above the page.

Motion

Motion answers something a person did: opening, expanding, confirming. The only unprompted motion is the double rule drawing under a verified total, once. When the system asks for reduced motion, every duration token becomes zero.

Components

Each component reads only its own layer (--pp-button-*, --pp-field-* and so on), and each of those points at a semantic token. The collapsed tables under every component are generated from the token sheet and show the resolved value. All of them map to Angular Material components through tokens; none is a new component. States in the matrices are forced with classes so they can be reviewed side by side; the real controls respond to hover and keyboard focus.

Status chips

Each state has its own shape, not only a colour: hollow, half-filled, tick, cross, a dashed-edge triangle for anything not yet verified, and two lines for the best offer. Teal belongs to the best offer alone.

Folio (provenance)

Every extracted number carries a three-part folio: the document id, the page or line, and the extraction confidence. The three bars summarise confidence: high above 90%, good above 75%, low below. It is always written left to right, because it is an identifier, not prose. One rule follows: a number with no folio is not shown as fact.

The decision sits under the thumb

Approve and reject live in a fixed bar above the navigation. Approve is wider; reject is outlined in red, not filled.

The total before the detail

Lines, total and the budget left share one card, so a typical request needs no scrolling before the decision. The total is not yet reconciled, so no double rule.

Same language, same shapes

Status chips keep their shapes; currency and digits follow the device language. In Arabic the back arrow flips and everything else follows the logical order.

48px touch targets

Every button and navigation item is at least 48px, whatever the density.

App shell

A sidebar named by the jobs people do, not by system modules. Groups by job, collapsible, the active group always open, state remembered per browser. Counts appear only for work waiting on you. At phone width the sidebar becomes a scrolling row. The logo picks its own variant: Arabic lockup in Arabic, dark lockup on navy.

The semantic layer feeds Material's system tokens; the component layer feeds each component's overrides mixin. Everything in this section was rendered in a real Angular 22.2.4 app and photographed; the screenshots close the section.

Known differences

      
Where Material 22.2.4 cannot match the specimens through tokens alone. None is papered over with internal CSS.

      
    
        
  • Hover is a translucent state layer (about 8% of the label colour), not the solid hover fills of the HTML specimens. Tonal buttons cannot gain a navy border on hover.
    • 
        
  • Outlined buttons stay transparent: Material 22.2.4 has no outlined container colour token, so on the page surface they show page grey where the specimen shows card white.
    • 
        
  • showProgress replaces the label with the spinner, so a loading button is a spinner alone. Pair it with disabled; the spinner colour is set for the disabled fill.
    • 
        
  • The focus ring is drawn by strong focus indicators 2px outside the control with one radius for every control, so round controls (radio, switch) get a rounded-square ring.
    • 
        
  • Form field labels float into the outline notch at 12px; the specimens put a 14px label above the control. Disabled fields keep a solid outline, not a dashed one.
    • 
        
  • The filled appearance has no room for a floating label at 40px. The app uses outline for all 203 fields; keep it the only appearance.
    • 
        
  • The needs-review chip draws a solid outline: chips have no outline-style token, so the dashed shape code becomes solid. Its glyph still carries the meaning.
    • 
        
  • Checkbox corners are 2px (no shape token); the specimens use 3px.
    • 
        
  • Tabs use one label weight for active and inactive tabs; the specimen sets the active tab in medium weight.
    • 
        
  • The toolbar has no bottom-border token: place a mat-divider under it, as the shell does.
    • 
        
  • Expansion panels have no outline token; a 1px spread shadow stands in for the border, so it does not double with an adjacent panel border.
    • 
        
  • The dialog backdrop and the best, selected and total table rows are styled through Ledger classes (backdropClass, .pp-best, aria-selected, .pp-total) because Material has no token for them. None touches a Material internal class.
