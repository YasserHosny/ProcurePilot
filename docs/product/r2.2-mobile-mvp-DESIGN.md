## Overview

ProcurePilot Mobile is B2B procurement software, not a consumer app: clean, trustworthy, and
efficient. Every screen exists to get a branch manager through a real-world task — restocking, a
quick signal, a status check — as fast as possible, or to give an approver a glanceable read on
what's waiting for them. Material Design 3, light theme only for this release, flat and
outlined over heavy shadows, fully bilingual (English / Arabic RTL) from the same components,
built to WCAG 2.1 AA. Every color pairing below is a verified AA contrast pair — don't substitute
a lighter or brighter shade of any status color without rechecking against white/black text.

## Colors

- **Primary (`#4F46E5`, indigo):** filled buttons, active navigation state, links, the
  Submitted status. Text on it: `onPrimary` white.
- **Secondary (`#5F6368`, slate):** body/metadata text, borders, Draft and Withdrawn statuses.
  Text on it: `onSecondary` white (6.05:1).
- **Tertiary (`#F59E0B`, amber):** a general accent/highlight color (e.g. a "new" badge) — text
  on it uses dark `onTertiary` (7.96:1), never white. Deliberately *not* reused for the Queued
  status below; they used to share a token and that conflated a routine, expected state with a
  warning.
- **Success (`#047857`, deep green):** the Approved status only. Deepened from a brighter green
  specifically so white label text stays AA-compliant (5.49:1) — a brighter green fails.
- **Error (`#DC2626`, red):** the Rejected status, destructive actions (e.g. sign out text).
  Deepened for the same reason as Success (4.83:1) — the previous, brighter red failed AA for
  small chip/label text (3.76:1).
- **Status: Queued (`#B45309`, deep amber, own token — not `tertiary`):** offline / not-yet-
  synced. A deliberately different, calmer amber than the accent color, and its own token, so a
  routine "will send later" state never reads as the same warning language as an actual alert.
  White text on it is 5.02:1.
- **Neutral (`#F1F3F4`) / Surface (`#FFFFFF`):** screen background vs. card/tile background.
- **Divider (`#E3E3E6`) vs. Outline (`#72777A`):** two different jobs — `divider` is a
  decorative hairline between list rows only; `outline` (4.53:1 against white) is what actually
  defines the edge of a text field or an outlined card/button. The two were conflated in an
  earlier draft, which measured at 1.28:1 against white — invisible in bright light, which
  matters for a phone held in a stockroom or loading dock.
- Status color is never the only signal — every status chip pairs its color with a distinct icon
  and a text label (see Components).

## Typography

One font stack per size — `"Roboto, 'Noto Sans Arabic', sans-serif"` — rather than separate
English/Arabic tokens: Latin characters render in Roboto, Arabic characters fall back to Noto Sans
Arabic automatically, on both the web and Flutter/Skia. (An earlier draft defined parallel
`*-ar` tokens that no component actually referenced, so Arabic screens would have silently
rendered in Roboto anyway — a font stack removes that failure mode entirely rather than relying on
every component remembering to pick the right variant.)

Six sizes: `display` (36px, bold — large stat numbers, e.g. an approver's pending-count card),
`headline` (24px — screen titles), `title` (18px — card/section headers), `bodyLarge` (16px — a
list tile's primary line, one step up from default body when it needs to read as the main
content), `body` (14px, the floor for anything read as a sentence), `label` (12px — the only size
allowed this small, for buttons/chips/badges).

## Layout

8px spacing grid (`spacing.xs` through `spacing.xl`), 16px standard screen padding, 48×48px
minimum interactive touch target on every tappable element (Material 3's real minimum, not iOS's
44). RTL is not an afterthought: every layout uses logical start/end, never left/right, and every
directional element (back arrows, chevrons, the top app bar's leading icon) mirrors in the Arabic
variant.

## Elevation & Depth

Flat and outlined by default — this is enterprise software, not a skeuomorphic consumer app. One
elevation level only, reserved for things that genuinely lift off the page: dialogs and bottom
sheets. Cards, list tiles, and the bottom nav sit flush with the surface beneath them. Use
`{colors.divider}` only for a decorative hairline between rows; use `{colors.outline}` for
anything that needs to actually read as a boundary — a text field, an outlined card, an outlined
button — divider is too faint for that job.

## Shapes

`rounded.sm` (8px) for text fields and small controls, `rounded.md` (12px) for cards and buttons —
rounded but not playful — `rounded.lg` (16px) for sheets and dialogs, `rounded.pill` for every
status chip and the search bar.

## Components

- **Buttons** — `buttonPrimary` (filled indigo, the one clear call-to-action per screen),
  `buttonSecondary` (outlined indigo), `buttonText` (text-only, for tertiary actions like "Not
  now" or "Use password instead"). Same height and corner radius across all three.
- **Status chip** — six variants, one per `Purchase Request` status plus the cross-cutting
  Queued state: `statusChipDraft`, `statusChipSubmitted`, `statusChipApproved`,
  `statusChipRejected`, `statusChipWithdrawn`, `statusChipQueued`. Each pairs its color with an
  icon (pencil / clock / check / X / undo / sync) inside the pill — color is reinforcement, the
  icon and label carry the meaning.
- **Cards** — `cardHero` (filled primary, used for exactly one action per screen — "New
  request"), `cardOutlined` (secondary actions and content cards), `cardTinted` (a flat, lightly
  tinted card for a non-interactive stat/summary, e.g. an approver's pending-count card — visually
  distinct from both hero and outlined so it never reads as tappable).
- **List tile** — leading icon, title, optional subtitle, optional trailing chip or switch.
- **Stepper** (`stepper`) — a quantity or count input with decrement/value/increment.
- **Filter chip** (`chipFilter`) — for horizontal option rows like "Recent items"; visually
  distinct from a status chip (square-ish `rounded.sm`, not `rounded.pill`) so the two are never
  confused.
- **Search bar** (`searchBar`) — a full-width pill-shaped input, Material 3's dedicated search
  pattern, not a plain text field.
- **Switch** (`switch`) — a standard toggle, for Settings' notification preference.
- **Segmented control** (`segmentedControl`) — for the language selector (EN / AR); not a
  rendered "preview thumbnail," just the two labeled segments.
- **Quoted callout** (`calloutQuote`) — a tinted block for an approver's decision comment on a
  request detail screen, visually distinct from ordinary body content.
- **Bottom action bar** (`bottomActionBar`) — the sticky bar holding a screen's primary and
  secondary buttons (e.g. "Save draft" / "Submit request").
- **Empty state** (`emptyState`) — generous padding, secondary text color, for a list screen with
  nothing in it yet.
- **Top app bar** — leading back/close icon, title; mirrors fully for RTL.
- **Bottom navigation** — three items only for this release (Home, Requests, Settings); outlined
  icon inactive, filled icon with primary-color tint active. 80px tall (Material 3's real
  navigation-bar height, not the older, shorter Material 2 bottom-nav).
- **Text field** (`textField`) — outlined using `{colors.outline}`, with label/hint/error states.
  A date picker and a branch-selector dropdown reuse this same outlined shell rather than
  introducing separate component styles.

## Do's and Don'ts

- **Do** pair every status indicator with an icon and a label. **Don't** rely on color alone for
  status — including on the low-stock report's stock level, which this release doesn't have; it's
  a one-tap signal, not an inventory reading.
- **Do** pair `statusChipQueued` with a sync or clock icon only. **Don't** use a warning triangle,
  exclamation badge, or any hazard-style icon for it — a queued/offline submission is a routine,
  expected state, not an error.
- **Do** keep exactly one `cardHero` per screen (the single primary action). **Don't** let a
  secondary card compete with it in size or color weight; use `cardTinted`, not `cardHero`, for a
  non-interactive stat like the approver's pending count.
- **Do** mirror every directional icon and use logical start/end spacing for Arabic. **Don't**
  hardcode left/right positioning anywhere.
- **Do** show buttons in their normal idle state in a static mockup. **Don't** depict a
  loading/spinner state as a screen's primary frame — that's a transient micro-interaction, note
  it separately if needed.
- **Don't** add a camera icon, barcode/scan control, or photo-attachment element to any R2.2
  screen — camera capture is a later release; every field in this release's request and
  low-stock flows is text/number/date input only.
- **Don't** add an approve/reject action anywhere on mobile in this release — the approver's home
  card is a read-only stat (large number + label), never a button, chip, or chevron.
- **Don't** substitute a brighter/lighter shade for `success`, `error`, or `statusQueued` without
  rechecking white-text contrast — these three were deliberately deepened from more "obvious"
  brand shades specifically to stay above 4.5:1 with white label text; a more saturated version of
  any of them likely fails.
